From the question to the query

“How many …?”
→COUNT(*) · COUNT(DISTINCT x)
“The worst / the top five”
→ORDER BY x DESC + LIMIT 5
“For each boiler / shift / day”
→GROUP BY that column
“Show the tag, not the id”
→JOIN the small table
“Only where …”
→WHERE rows · HAVING groups
“How often is it above X?”
→SUM(CASE WHEN x>X THEN 1 ELSE 0 END)
“Per tonne / per hour / per day”
→divide one SUM by another
“Is it getting worse?”
→GROUP BY strftime('%W', ts)

Traps that catch everybody

  • Text needs single quotes: code = 'B-2103', never "B-2103". Numbers take none: boiler_id = 2.
  • WHERE filters rows, HAVING filters groups — WHERE AVG(x) > 150 is an error.
  • Write 100.0, not 100. Whole numbers divide into whole numbers, so 3/4 is 0 and percentages come out zero.
  • A rate for a whole month is SUM(fuel_gj)/SUM(steam_t), not AVG(fuel_gj/steam_t) — the second lets a quiet day count as much as a busy one.
  • ts holds a date and a time, so match the start: ts LIKE '2026-04-01%'.
  • Anything in SELECT beside an aggregate must also appear in GROUP BY.
  • Put COUNT(*) next to every average — it says how many rows went into it.

The shape of a real query

-- gas per tonne of steam, worst boiler first
SELECT   b.code,
         ROUND(SUM(d.fuel_gj) / SUM(d.steam_t), 3) AS gj_per_tonne,
         COUNT(*) AS n_days
FROM     daily_logs d
JOIN     boilers    b  ON  b.boiler_id = d.boiler_id
WHERE    d.log_date LIKE '2026-04%'
GROUP BY b.code
HAVING   COUNT(*) > 25
ORDER BY gj_per_tonne DESC
Pieces worth remembering: AVG MIN MAX SUM COUNT · ROUND(x, 1) · substr(ts, 1, 10) the day · strftime('%W', ts) the week · x IN ('B','C') · (SELECT AVG(x) FROM t) used as one value
