Traps that catch everybody

  • Text needs single quotes: code = 'B-2103', never "B-2103". Numbers take none.
  • WHERE filters rows, HAVING filters groups — WHERE AVG(x)>150 is an error.
  • Check MIN and MAX before you trust an AVG — a dead thermocouple reading 0.0 and a spike of 511.8 are both hiding in readings.
  • A rate is SUM(fuel_gj)/SUM(steam_t), not AVG(fuel_gj/steam_t) — the second lets a quiet day count as much as a busy one.
  • Anything in SELECT beside an aggregate must appear in GROUP BY too.
  • Put COUNT(*) next to every average — unequal counts mean an outage, a new machine, or missing data.
  • A join need not be on an id — ON f.month = substr(log_date,1,7) works.

The shape of a real query

-- is any boiler getting worse?
SELECT   substr(d.log_date, 1, 7) AS month,
         b.code,
         ROUND(SUM(d.fuel_gj)/SUM(d.steam_t), 3) AS gj_t,
         COUNT(*) AS n_days
FROM     daily_logs d
JOIN     boilers    b  ON  b.boiler_id = d.boiler_id
GROUP BY substr(d.log_date, 1, 7), b.code
HAVING   COUNT(*) > 20
ORDER BY b.code, month
Pieces worth remembering: AVG MIN MAX SUM COUNT · ROUND(x, 1) · substr(ts, 1, 10) the day · substr(ts, 1, 7) the month · x IN ('B','C') · (SELECT AVG(x) FROM t) as one value
